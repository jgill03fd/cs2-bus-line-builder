# Calibration: 3840x2160 client (reference space 1920x1080)

Measured 2026-11-08 with a 4K display (3840x2160, Windows scaling 300%), Cities: Skylines II
fullscreen. `gamewin.ps1` takes coordinates as client pixels divided by `-Scale`; with `-Scale 0.5` every point below is in
the 1920x1080 reference space (client x 0.5), the same space as a `shot -Scale 0.5` image.

## Why a profile per resolution
The original repo assumed a 1280x768 client (centre 640,384). Click positions, the tooltip search box and the idle cursor
spot all depend on the client size and UI scale. The screen centre is derived (client x scale / 2); the UI-anchored points
are not, so they live in `profiles/<W>x<H>.json`. The loader stops if no profile exists for the current client size, because
a wrong click with a build tool active can delete stops from routes.

## Status
- Converted for the repo loader on branch calibration-3840x2160-converted: the profile holds client pixels (these reference values x 2) because the scripts pass -Scale 1.0. shelter_pre_hover is not measured yet, so place_shelters and build_line must not run on this profile.
- Points came from an in-game session; the bus stop and line tool positions were used successfully for placing stops and drawing a line.
- The toolkit scripts are parse-checked. The loader's scale handling and the pixel checks (tooltip green/orange, teal stop icon) have NOT yet been run end to end. Test on one short loop after saving a checkpoint.
- UI scale was not recorded separately. If the in-game UI scale changes, re-measure the ui points.
- Note for performance: rendering at 4K is demanding; a lower in-game resolution would change the client size and need its own profile.
